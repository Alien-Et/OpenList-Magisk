# 04. 更新与回滚

## 数据来源

```
GET https://api.github.com/repos/OpenListTeam/OpenList/releases/latest
```

Android 资产：

| 资产 | 架构 |
|---|---|
| `openlist-android-arm64.tar.gz` | arm64-v8a |
| `openlist-android-arm.tar.gz` | armeabi-v7a / armeabi |
| `openlist-android-amd64.tar.gz` | x86_64 |
| `openlist-android-386.tar.gz` | x86 |

另有 `md5-android.txt`，格式 `hash  ./文件名`。

## 选择资产

`ro.product.cpu.abi` → 资产名，`getprop` 不可用时默认 arm64。

## 版本列表与最新版本检查

`versions` / `check` 只走 GitHub 官方 API，不套代理：

```
GET /repos/OpenListTeam/OpenList/releases?per_page=100&page=N   ← 翻页直到不满 100 条
```

- 每个 release 用「`tag_name` 在前、`published_at` 在后」的顺序配对，draft（`published_at`
  为 null）靠"新 TAG 覆盖旧 TAG"自愈，不会整体错位
- 结果按 `^v[0-9]` 过滤（`beta`、`beta-media` 这类分支 tag 不进列表）
- 5 分钟缓存，避免反复消耗 60 次/小时的未认证额度
- 403 时区分「限流」和「拒绝访问」，并把响应体前 160 字回传 `debug=`
- 可选 token：`<模块目录>/.github_token`（一行 PAT）→ 5000 次/小时

## 无代理环境（国内直连）

- `check` / `versions` 的 API 请求 8 秒连接超时、20 秒总超时，失败立刻给结论，
  不再挂 30 秒让人以为"没反应"
- API 不可达时：
  - 版本列表 → 用上次成功的缓存，返回 `stale=1` + `error=`，WebUI 在列表底部标「离线缓存」
  - 检查更新 → 用缓存里的最新版本，`updateHint` 显示「显示的是缓存版本；下载会走镜像」
  - 指定版本安装 → 完全跳过 API，按固定路径拼下载地址
- 下载本身走镜像（ghfast / gh-proxy / ghproxy 实测对 `github.com` 资产返回 206 可用），
  下载期间每 2 秒刷新「已下载 N MB」，不再是一动不动

## 下载与代理

直连失败后依次尝试：

1. `GH_PROXY` 环境变量
2. `https://ghfast.top/`
3. `https://gh-proxy.com/`
4. `https://ghproxy.net/`

代理只拼在 `github.com/...` 前面，不拼 `api.github.com`（多数代理不转发 API）。

下载优先 curl，其次 busybox wget。

## 校验

下载 `md5-android.txt`，用 awk 按文件名取 md5，`md5sum` 对比。校验失败直接中止，不替换。

md5 文件缺失时跳过校验（release 偶发缺少），不阻断更新。

## 替换流程

1. `pkill -f "$BIN server"`
2. 轮询 10×0.5s 等进程退出，超时 `pkill -9`
3. 备份 `$BIN` → `$BIN.bak`
4. `cp` 新文件到 `$BIN.new`（同目录，保证 rename 原子）
5. `chmod 755`，`mv -f` 覆盖
6. 目标是 `/system/bin` 时 `chcon u:object_r:system_file:s0`
7. `sh service.sh` 重新拉起，轮询 15 秒

## 版本同步

启动成功后写 `module.prop`：

```
version=v4.2.11
versionCode=40211
```

`versionCode = 主版本×10000 + 次版本×100 + 修订号`，与 CI 的算法一致。

用 10000 作主版本权重，是为了避免次版本到两位数时撞号：旧公式 `×1000 + ×100` 下，`v4.10.0` 与 `v5.0.0` 都会算成 5000。现行公式下两者分别是 41000 和 50000。代价是次版本、修订号都要小于 100。

## 回滚

启动失败时：

1. `cp $BIN.bak $BIN`
2. `chmod 755`
3. 重新启动旧版本
4. 输出 `rolled_back=1`、`result=fail`、`error=新版本启动失败，已回滚到 x.y.z`

`module.prop` 版本号保持原样，不写新版本。

## 限制

- 下载期间只显示阶段，没有百分比（`exec` 一次性返回，进度靠轮询进度文件）
- 没有断点续传，中断后重新下载
- 没有检查剩余空间（包 ~58MB，解压后 ~165MB）
- 依赖 GitHub 可达，代理全挂时无法更新
