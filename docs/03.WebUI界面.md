# 03. WebUI 界面

## 文件

```
webroot/
├── index.html   页面结构
├── app.js       ksu.exec 兼容层、参数校验、事件
└── style.css    主题变量、毛玻璃、组件
```

无构建步骤，直接放进模块目录。KernelSU/APatch 安装时自动设置 `webroot` 权限和 SELinux 上下文，不要手动 chmod。

**WebUI 有两种加载方式，写法必须同时兼容**：

| 方式 | 谁来加载 | 特点 |
|---|---|---|
| 模块 WebUI | root 管理器（ksud 起的本地 HTTP 服务） | 支持 query、支持自定义响应头 |
| 直接打开 | 浏览器 / NP 的文件预览 | `file://` 协议 |

所以资源引用只能写裸路径 `./style.css`、`./app.js`，**不能加 `?v=时间戳`**：
`file://` 下 Chromium 把 `?v=1` 当文件名的一部分，直接 404，页面退化成裸 HTML
（表现就是「root 管理器里正常、别处预览错位溢出」）。改完 CSS/JS 靠文件 mtime
让 WebView 重新读取，不要指望 query 绕缓存。

同理，`data-pane`（面板归属）与 `data-tab`（按钮目标 + body 当前标签）必须分开，
但 `<body>` 只能带 `data-tab` —— 它是状态载体，不是面板。

## 底部导航

4 个标签，底部悬浮大圆角磨砂玻璃条（左右各留 14px、`border-radius:28px`、
`backdrop-filter: blur(28px) saturate(190%)`）；页面滚动超过 40px 时整体上浮 3px。

定位写法是 `left:14px; right:14px; margin:0 auto; max-width:572px`，**不要改成
`left:50%` + `transform:translateX(-50%)`**：部分 WebView 用这套算出的宽度会超过视口，
超出的部分既把导航条自己推出屏幕（第 4 个按钮看不见），又给整页制造横向溢出，
连带卡片右侧也被裁掉。`margin:auto` 在两侧 inset 都存在时会自动平分剩余空间，同样居中，
且完全依赖布局而不依赖变换。

窄屏下 `.tab` 用 `flex:1 1 0; min-width:0`，中文标签（「版本控制」四个字）不会把容器撑破。
当前标签记在 `localStorage` 的 `openlist.tab`，刷新后停在上次的位置。

| 标签 | data-tab | 内容 |
|---|---|---|
| 仪表盘 | `dash` | 概览指标 + 服务状态 |
| 版本控制 | `version` | 版本与更新、所有版本、下载镜像 |
| 配置 | `config` | 下载配置、管理员账号、路径体检、迁移 |
| 更多 | `more` | 存储、离线任务、服务日志、关于 |

显隐不靠 JS 切 DOM，用一条选择器解决：每个区块和它的小标题都带同一个 `data-pane` 值，
切标签只改 `body` 的一个属性 ——

```css
body[data-tab="dash"] [data-pane]:not([data-pane="dash"]) { display: none }
/* version / config / more 同理 */
```

**面板用 `data-pane`、导航按钮用 `data-tab`，两组属性必须分开。**
早期两者共用 `data-tab` 时，`[data-tab]:not([data-tab="dash"])` 会把「版本控制 / 配置 / 更多」
三个按钮本身也判成要隐藏的节点，结果底栏只剩一个图标。

`onTabEnter` 负责按需懒加载：进「版本控制」才查更新，进「配置」才拉配置和路径体检，
进「更多」才拉存储 / 任务 / 日志。没进过的标签不会白发请求。

## 仪表盘

`control.sh stats` 读 `/proc`：两次采样（间隔 0.3 秒）算 CPU 占用，再取 `meminfo`、`df`、
`loadavg`、`uptime`。停留在仪表盘标签且页面在前台时每 4 秒轮询一次，切走或页面隐藏立即
`stopStats()`，不在后台空转。

| 卡片 | 数据 |
|---|---|
| CPU | 使用率百分比 + 进展条，副标题是逻辑核心数 |
| 内存 | 已用 / 总量 + 百分比 |
| 磁盘 | 模块所在分区已用 / 总量 + 百分比 |
| 负载 | 1 / 5 / 15 分钟平均负载、运行时长、核心数 |

## 页面模块

| 区块 | 内容 |
|---|---|
| 状态 | 运行中/已停止、地址、PID、启停/重启/打开网页 |
| 路径体检 | 3 个二进制位置与 2 个数据目录的占用；二进制可一键清理多余副本，数据目录可「切换到此」或输入目录名确认删除 |
| 所有版本 | 全部 release 列表（含历史），每行显示版本、日期、当前标记或「安装」按钮，用于升级与回退 |
| 版本与更新 | 模块版本、OpenList 版本、最新版本、架构、资产、检查更新、立即更新 |
| 下载配置 | 端口、Token、目标路径、离线引擎、删除策略、预设路径 |
| 管理员账号 | 用户名（可选）、新密码、确认密码 |
| 存储 | 列表、启用/禁用、全部重载 |
| 离线任务 | 进行中任务、进度、取消 |
| 迁移 | 数据目录、二进制路径、脚本路径自检/修复 |
| 服务日志 | 「服务日志 / 程序输出」两个标签（service.log / openlist.log）、刷新、清空 |
| 关于 | 项目链接、Release 链接 |

## 版本号怎么显示

模块版本和 OpenList 版本是两个东西，界面分开显示：

- **模块版本** 读 `module.prop` 的 `version`：架构包是 OpenList 版本（`v4.2.10`），纯在线包是模块自身的日期版本（`2026.11.24-1`）。
- **OpenList 版本** 读 `.bin_version`，**模块目录和数据目录各存一份**，模块目录优先。
  数据目录那份是关键：模块目录每次升级都会被整体替换，只存模块目录的话，升级重启后必然变成 unknown。
  两份都读不到才去问二进制自己 —— 依次试 `version` / `--version` / `-v`（不同版本支持的参数不一样），
  取输出前 5 行里第一个 `X.Y.Z`，成功后顺手把结果写回两处缓存。
- 服务启动成功时 `service.sh` 也会写一次 `.bin_version`（双写），所以「重启服务」本身就能把版本号补回来。
- 无论来源是文件还是二进制，最终都规范成带 `v` 前缀的 `vX.Y.Z`；「所有版本」里的「当前」标记按 `X.Y.Z` 比较，
  不会因为一边有 `v`、一边没有就标不出来。
- 分开显示之后，online 用户切二进制时模块版本不会被顶掉。

## 操作反馈

所有按钮都走 `toast()` 提示：

- **版本切换** → `✅ 已切换到 vX.Y.Z（模块版本 …），服务已重新启动`；失败时原因同时写进提示条和 toast，不会再停在「正在切换…」
- **保存配置** → 端口变了后端会自动重启一次，toast 直接说明「已自动重启」还是「重启失败，请手动点重启服务」
- **刷新 / 测速 / 存储列表 / 任务列表** → 都有完成提示

端口写在 `config.json` 里，二进制只在启动时读一次，所以改端口必须重启才生效 —— 后端 `config-save` 会对比新旧 `PORT` 并顺手重启，不用用户自己去点。

## 主题

三态：**自动 / 浅色 / 深色**，顶部右侧按钮循环切换。

- 状态落在 `html[data-theme="light|dark"]`，CSS 只维护两套变量
- 自动模式监听 `matchMedia('(prefers-color-scheme: dark)')`
- 选择存 `localStorage`，键名 `openlist.theme`
- `color-scheme` 跟着主题走，让表单控件按对应模式渲染

不使用三套选择器叠加，避免 `auto` 和 `dark` 同时命中。

## 毛玻璃

- 卡片 26px 圆角、半透明背景、`backdrop-filter: blur(24px) saturate(170%)`
- `body::before` 铺三层径向光斑，给毛玻璃提供底色
- 边框、阴影、内高光统一用变量
- 不支持 `backdrop-filter` 时用 `@supports` 降级成不透明卡片

按钮、输入框、日志框、toast 共用同一套圆角和材质。

## 自定义组件

### 下拉

不用原生 `<select>`：它的弹层由系统渲染，深色页面下会出现白底 + 浅色文字，`option` 样式和 `color-scheme` 都压不住。

改为 `.select`：

```
.select > .select-btn + .select-menu[hidden]
```

- 点击按钮展开，点选项写入 `dataset.value`
- 点击页面其他位置收起
- 选中项高亮，颜色完全由页面控制

### 预设路径

迁移页用 `.chips > .chip-btn`：

- 点击填充输入框并高亮
- 手动输入时自动匹配高亮
- 保留自定义输入，不限制在预设里

### 迁移页：两个表单一致

数据目录和二进制都用同一套 `.chips` 点选，不再给二进制单独留一个输入框：

- 只显示「非当前」的候选（`filterChips` 按 `status` 返回的 `data_dir` / `bin` 过滤）
- 只剩一个候选时自动选中
- 点「开始迁移」先变成「再点一次确认」，4 秒内二次点击才执行

### 动作完成后即时刷新

迁移数据 / 迁移二进制 / 清理副本 / 修复路径这类会改变磁盘布局的操作，成功后统一走
`refreshAll()`，按顺序刷新三块内容：

1. `refresh()` → 状态、版本、`DATA_DIR` / `OPENLIST_BINARY` 路径胶囊（`filterChips` 重新算「非当前」候选）
2. `loadScan()` → 路径体检里的二进制与数据目录清单、占用、`当前/多余` 标签
3. `loadLog()` → 当前选中的日志页

所以迁移成功、源目录被删掉之后，界面立刻显示新路径和新的体检结果，不需要手动点刷新。

## 下载镜像

「下载镜像」卡片只管**二进制下载**（`github.com` 资源），不涉及版本列表（那是 `api.github.com`）。

- 下拉栏：`自动选择` / `直连` / 15 个国内镜像 / `自定义…`
- 每个镜像后面显示**实测延迟**（打开页面自动测速一次，可点「测速」重测）
  - `123 ms` 正常
  - `超时` 连不上
  - `✗ 429` 被限流、`✗ 404` 该镜像不转发这个路径
- 选中「自定义…」后填前缀（`https://your-mirror/`），保存后写入 `<数据目录>/mirror.conf`
- 放数据目录而不是模块目录：模块更新会整体替换模块目录，配置会丢；放数据目录还能跟着数据迁移走

## 加载策略（避免满屏"加载中…"）

打开 WebUI 时各区块**并行**发起 `ksu.exec`，不再串成一条链：

| 区块 | 耗时来源 | 优化 |
|---|---|---|
| 状态 | `control.sh status` | 快 |
| 路径体检 | `find` 整个数据目录统计文件数 | 结果缓存 60 秒（内存）+ 10 分钟（localStorage 先铺上次结果）；迁移/清理后传 `force` 强制重扫 |
| 所有版本 | GitHub releases JSON（约 5.4 MB） | curl `--compressed` 走 gzip（实测 5.39 MB → 412 KB）；结果缓存 5 分钟（control.sh）+ localStorage 先铺上次列表 |
| 存储 / 任务 | OpenList 管理 API | 并行，不阻塞其他区块 |

`refreshAll()`（迁移、清理、修复路径之后）会强制重扫并刷新日志。

## 无 root 接口时的降级

没有 `window.ksu`（普通浏览器打开）时：

- 顶部显示「无 root 接口」
- 状态、日志、存储、任务显示说明文字
- 操作按钮全部禁用
- 主题切换、下拉、预设仍然可用，方便预览界面
- 加 `?demo=1`（或把文件命名为 `preview.html`）会启用演示数据，浏览器里能看完整布局，不需要 root

## 渲染安全

- 所有命令输出、日志、存储/任务字段用 `textContent` 或 DOM 节点，不拼 `innerHTML`
- 不引外部 CDN，WebUI 离线运行
- 用户输入在 JS 侧先校验，`control.sh` 再校验一次
- Token / 密码输入框不用 `type=password`，改成 `type=text` + `.mask`（`-webkit-text-security:disc`）。
  部分 WebView 自带的密码管理器/自动填充会抢焦点，甚至让 `type=password` 的框完全输不进字；
  改成遮罩方案后输入行为与普通输入框一致，管理员卡片还带「显示密码」切换

## 更新进度

WebUI 不直接跑 `update`：先 `update-bg`（立即返回），再每 1.5 秒 `update-status`。`control.sh update` 把 `stage=` 写到 `/data/local/tmp/openlist_update.progress`，轮询把它映射成中文阶段：

```
resolve → 获取版本信息
download → 下载二进制
extract → 解压
stop → 停止服务
replace → 替换二进制
start → 启动服务
```

`update-status` 返回 `running=1` 就继续轮询（上限 90 分钟）；返回 `done=1` 时把子进程的 `result=` / `error=` 一并带回，
失败原因优先用 `error=`，没有就用宿主的 stderr / 退出码，不再只显示「更新失败」四个字。
