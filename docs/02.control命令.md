# 02. control 命令

`control.sh` 是模块的统一控制入口，WebUI、终端、脚本都调它。

## 输出协议

每行一个 `key=value`，结束行：

```
result=ok
```

或

```
result=fail
error=具体原因
```

失败时退出码为 1。WebUI 的 `ctl()` 按 `=` 切分解析，`api` 命令例外（直接输出原始 JSON）。

## 命令表

| 命令 | 说明 |
|---|---|
| `status` | 运行状态、PID、端口、IP、版本、数据目录、二进制、模块目录、ABI |
| `start` | 后台拉起 `service.sh`，轮询 15 秒确认进程 |
| `stop` | `pkill` → 等 10×0.5s → `pkill -9`，写 module.prop「已停止」 |
| `restart` | stop + start |
| `check` | 请求 GitHub Release，返回 current / latest / asset / abi / up_to_date |
| `versions` | 列出所有 release（含历史），每行 `版本|发布日期`，5 分钟缓存。只走 GitHub 官方 API：`per_page=100` 按页翻到底，不套代理、不做 HTML 兜底 |
| `scan` | 列出 3 个二进制位置与 2 个数据目录的实际占用，标出当前使用的那份 |
| `clean-bins` | 删除非当前使用的二进制副本（当前使用的不动） |
| `delete-data <b64dir>` | 删除指定数据目录，拒绝当前使用中的；目录内有二进制时保留 `bin` |
| `use-data <b64dir>` | 切换数据目录：只改 `service.sh` 与 `config.json` 的路径，不搬文件 |
| `update [--force] [--asset NAME] [--proxy URL] [--tag vX.Y.Z]` | 下载 → md5 → 解压 → 停 → 备份 → 替换 → 启动 → 同步版本；`--tag` 指定版本用于回退 |
| `logs [行数] [service\|openlist]` | tail `service.log` 或 `openlist.log`，默认 120 行 / service |
| `config-get` | 读 `offline.conf` 的 7 个键 |
| `config-save <base64>` | 白名单校验后原子写入 |
| `passwd <base64密码> [base64用户名]` | API 优先在线改，失败回退 CLI |
| `token` | 取 admin token（CLI → offline.conf，缓存 120s） |
| `api <GET\|POST> <path> [base64 body]` | 带 token 转发到 `127.0.0.1:端口` |
| `migrate-data <base64目录>` | 迁移数据目录：复制+校验后同步 config.json，然后**删除源目录**（源目录内的二进制先搬到模块 `bin/`） |
| `migrate-bin <base64路径>` | 迁移二进制：复制+校验后同步 service.sh/action.sh，然后**删除旧二进制**（旧 `bin/` 空了顺手收掉） |
| `fix-paths` | 对齐 action.sh 与 config.json 的路径 |
| `version` | 只读 module.prop 的 version |

## GitHub API 与限流

`check` / `versions` / `update` 的版本查询都走 `api.github.com`（官方接口），带
`User-Agent: OpenList-Magisk` 和 `Accept: application/vnd.github+json`。

未认证额度是 **60 次/小时（按出口 IP）**，打满会返回 403。此时 `control.sh` 会明确报
「GitHub API 限流」，并把响应体前 160 字放进 `debug=`，不再是一句笼统的「解析失败」。

想提高额度：把 GitHub PAT 写进 `<模块目录>/.github_token`（一行，不要换行），
请求会自动加 `Authorization: Bearer`，额度变 5000 次/小时。也可用环境变量 `GH_TOKEN` 覆盖。

> 国内代理（ghfast / gh-proxy / ghproxy）**不转发 `api.github.com`**，实测都是 403，
> 所以版本查询不再走代理；只有下载 `github.com/...` 上的二进制资产时才会拼代理。

## 参数编码

路径、密码、用户名、配置内容全部用 **base64** 传参，避免 shell 拼接和引号问题。

```sh
B64=$(printf '/data/adb/openlist' | base64 -w0)
sh control.sh migrate-data "$B64"
```

`config-save` 传的是完整 `offline.conf` 内容的 base64。

## 状态探测

- PID：`pgrep -f "$OPENLIST_BINARY server"`，回退 `pgrep -f "openlist server"`
- 端口：优先读 `$DATA_DIR/config.json` 的 `http_port`，其次 `ss -ltnp`、`netstat -tlnp`，默认 5244
- IP：优先从 `module.prop` 的 description 提取，其次 `ip route get 1.1.1.1`
- 版本：`module.prop` 的 `version`

## token

```sh
openlist admin token --data "$DATA_DIR"
```

优先用 CLI（可靠），失败读 `offline.conf` 的 `TOKEN=`。

缓存 `/data/local/tmp/openlist_token.cache`，120 秒有效，权限 `600`。

## api

```sh
sh control.sh api GET /api/admin/storage/list
sh control.sh api POST /api/admin/storage/enable "$(printf '{"id":1}' | base64 -w0)"
```

- 只允许 `/api/*`
- 自动带 `Authorization: <token>`
- curl 优先；没有 curl 用 busybox wget；都没有则失败
- 输出原始响应体，由 WebUI 做 `JSON.parse`

## 管理员账号

流程：

1. `GET /api/admin/user/get?id=1`
2. 从响应里取出 `data` 对象（不是整个 `{"code":200,"data":...}`）
3. 替换 `username` / `password`
4. `POST /api/admin/user/update`

注意：

- 必须提交**完整 User 对象**。`UpdateUser` 只补齐 `PwdHash/Salt/OtpSecret`，`base_path / permission / allow_ldap / sso_id` 用提交值，漏传会被清零。
- `role` 不可改；admin 不可禁用；`username` 有唯一约束。
- 在线改密不重启，admin token 不变。
- 无 curl 时回退 `openlist admin set`（会短暂停服务）；用户名在 CLI 分支用 sqlite3 兜底。

## fix-paths

用于迁移后路径不一致：

- 以 `service.sh` 的 `OPENLIST_BINARY` 为准，同步 `action.sh`
- 从 `config.json` 的 `db_file` 推断旧数据目录，把所有 `"旧目录` 前缀替换为当前 `DATA_DIR`

输出 `fixed_action_bin` / `fixed_config` / `fixed`。

## 校验规则

| 字段 | 规则 |
|---|---|
| PORT | 1–65535 |
| TOKEN | `^[A-Za-z0-9._-]*$` |
| HOST | `^[A-Za-z0-9._:-]+$` |
| PATH | 以 `/` 开头，禁止空格、引号、反引号、`; \| & $ ( ) < > * ? ! ~ \` |
| 用户名 | `^[A-Za-z0-9_.-]{3,32}$` |
| 迁移目标 | `/data/*`、`/sdcard/*`、`/storage/*`；禁止模块目录内、数据目录父子关系 |
| 二进制目标 | `/data/*`、`$MODDIR/system/bin/*`；`/system/bin/*` 自动映射到模块 |
