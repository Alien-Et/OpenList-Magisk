# 07. 总结

## 完成的内容

**control.sh（新增）**

统一控制入口，16 个命令覆盖状态、启停、更新、日志、配置、账号、存储、任务、迁移、路径修复。输出 `key=value`，失败带原因。

**webroot（新增）**

KernelSU / APatch 的模块 WebUI，无构建步骤，毛玻璃 + 大圆角，自动/浅色/深色三态主题，自定义下拉和预设胶囊。

**其它**

- `customize.sh` 安装时确保 `control.sh` 可执行
- `uninstall.sh` / `uninstall-user.sh` 改为动态解析路径
- README 与 docs 同步

## 关键设计决策

1. **业务逻辑集中在 `control.sh`**
   WebUI 只是前端，Magisk 用同一份命令行，三家功能一致，不维护两套逻辑。

2. **改密走 OpenList 管理 API**
   `GET user/get` → 改字段 → `POST user/update`，在线生效，不重启。必须提交完整 User 对象，否则 `base_path/permission/allow_ldap` 会被清零。

3. **更新先启动成功再写版本号**
   失败自动回滚 `.bak`，版本号保持不变，避免「显示新版本但实际是旧二进制」。

4. **迁移同步 `config.json`**
   只改 `service.sh` 不够，OpenList 读的是 config.json 里的绝对路径。

5. **`/system/bin` 映射到模块目录**
   overlay 写入重启即丢，统一写真实文件，靠模块挂载。

6. **不用原生 `<select>`**
   系统弹层不可控，深色下白底白字，改自定义下拉。

## 修过的 bug

| 问题 | 处理 |
|---|---|
| 更新后 `module.prop` 版本不同步 | 启动成功后写 version/versionCode |
| 更新启动失败不自动回滚 | 自动恢复 `.bak` 并重启旧版 |
| `migrate-bin` 写运行时 `/system/bin` | 映射到 `$MODDIR/system/bin` |
| 深色下下拉框文字不可见 | 自定义下拉组件 |
| WebUI 停止不写 `module.prop` | `cmd_stop` 写「已停止」 |
| 迁移后 `config.json` 路径仍是旧的 | 迁移时同步绝对路径 |
| 卸载脚本写死路径 | 从 service.sh 动态解析 |
| 迁移目标可套娃/覆盖模块 | 增加互斥校验 |
| token 缓存权限过宽 | chmod 600 |
| `control.sh` 读出的 `$MODDIR` 不展开，选 2/3 装完启动报「二进制不存在」 | 加 `expand_moddir()` |
| 安装菜单里 `$MODDIR` 未定义，显示成「2、/bin」 | 补 `MODDIR="${MODDIR:-$MODROOT}"` |
| 相对路径调用时 `MODDIR="${0%/*}"` 得到文件名 | 三个脚本统一 `cd + pwd` 转绝对 |
| `getevent` 不可用时按键菜单无限空转 | 约 90 秒无输入按默认选项继续 |
| 脚本权限记录为 644 | 六个脚本统一 755 |
| 卸载（Magisk）无条件删数据 | 默认保留数据，仅删二进制；`touch .delete_data_on_uninstall` 才连数据删 |
| `$ARCH` 被 `ro.product.cpu.abi` 覆盖 | 优先用框架 `$ARCH`，x86 明确 abort |
| 数据目录不可写仍继续安装 | 增加可写性检查与警告 |
| 密码菜单排在「安装完成」之后 | 移到完成提示之前 |
| WebUI 硬编码模块目录 | 从 `location.pathname` 推导 |
| admin 未初始化，所有 `/api/admin/*` 报 500 record not found | 交给网页安装向导创建；WebUI 遇到 record not found 时提示先去网页完成初始化 |
| 迁移后源目录仍有数据 | 迁移改为「移动」：等进程退出 → 复制 → 校验 → 清空源目录（保留源 bin） |
| `module.prop` 显示 172.x 虚拟网卡地址 | IP 优先取默认路由 `src`，排除 `172.16-31` 网段 |
| `storage/list` 返回分页对象被当成数组 | 前端兼容 `data.content`，并补 `?page=1&per_page=100` |

## 测试记录

- 假模块目录：status / start / stop / config-save / migrate-data / migrate-bin / passwd / fix-paths
- 端口 99999、0 被拒；路径注入字符被拒；中文路径通过
- 真实 update：下载 165MB ARM64 包，md5 通过，替换成功；坏包触发回滚
- 迁移：config.json 四个绝对路径全部对齐
- fix-paths：action.sh 与 config.json 旧路径被修正
- 模拟安装：3×2×2 = 12 种选项组合全部 `exit=0`、无 `abort`，落点与 `service.sh` 变量符合预期（见 [06.安装选项矩阵](06.安装选项矩阵.md)）
- 运行时：用 `ip` / `getprop` / `ss` 桩跑 `service.sh`，能拉起进程并把 `module.prop` 改成「【运行中】当前地址：http://192.168.1.100:5244 | PID…」
- 架构：`arm64` / `arm` 分别装对应二进制，`x86_64` 正确 `abort`
- 卸载：无标记时只删二进制、保留数据目录；有 `.delete_data_on_uninstall` 时整目录删除
