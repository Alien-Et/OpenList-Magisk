# 01. WebUI 与 control.sh

## 背景

issue #36 提出用 WebUI 替代热更新。KernelSU/APatch 支持模块 `webroot`，Magisk 不支持，所以把业务逻辑收敛到 `control.sh`，WebUI 只做界面。

## 架构

```
webroot/index.html + app.js   (KernelSU / APatch)
        │ ksu.exec
        ▼
control.sh                    (root CLI，唯一事实来源)
   ├── status / start / stop / restart
   ├── check / update
   ├── logs
   ├── config-get / config-save
   ├── passwd
   └── migrate-data / migrate-bin
```

- WebUI 不做业务判断，只传参、校验、展示。
- Magisk 用户在终端执行同一份 `control.sh`，功能不丢。
- `action.sh` 保持原样，WebUI 的启停走 `control.sh`，不依赖 action 的输出。

## control.sh

输出统一 `key=value`，结束行 `result=ok` 或 `result=fail` + `error=`。

| 命令 | 说明 |
|---|---|
| `status` | running/pid/port/ip/version/data_dir/bin/abi |
| `start` / `stop` / `restart` | 后台调用 `service.sh` 或 pkill，轮询 15s 确认 |
| `check` | 请求 GitHub Release，返回 current/latest/asset/up_to_date |
| `update [--force] [--asset N] [--proxy URL]` | 下载 → md5 校验 → 解压 → 停 → 备份 → 替换 → 启动 |
| `logs [n]` | tail service.log |
| `config-get` | 读 offline.conf 的 7 个键 |
| `config-save <base64>` | 白名单校验后原子写入 |
| `passwd <base64>` | API 优先在线改密（不重启），CLI 兜底；第二个参数可传新用户名 |
| `token` | 取 admin token（CLI 优先，offline.conf 兜底，缓存 120s） |
| `api <GET\|POST> <path> [base64]` | 带 token 转发到 `127.0.0.1:端口`，curl 优先、busybox wget 兜底 |
- `migrate-data <base64>` | 复制 → 文件数/data.db 校验 → 改 service.sh 的 DATA_DIR → 同步 config.json 里的绝对路径 → 启动 |
| `migrate-bin <base64>` | 复制 → chmod/chcon → 改 service.sh/action.sh → 启动 |

### 二进制更新流程

1. `GET api.github.com/.../releases/latest`
2. 按 `ro.product.cpu.abi` 选 `android-arm64 / android-arm / android-amd64 / android-386`
3. 直连失败依次尝试 `GH_PROXY`、内置代理前缀
4. 用 `md5-android.txt` 校验
5. `pkill` → 等进程退出 → `cp` 到同目录 `.new` → `mv` 原子替换
6. 启动成功后同步 `module.prop` 的 `version` / `versionCode`（`v4.2.11 → 4211`）
7. 启动失败自动用 `.bak` 回滚并重启旧版本，`module.prop` 版本号保持不变

### 安全

- 所有外部输入用 base64 传给 control.sh，避免 shell 拼接。
- `config-save` 二次校验：端口 1–65535、Token `[A-Za-z0-9._-]`、路径必须以 `/` 开头且禁止空格/引号/`;|&$` 等。
- WebUI 渲染一律 `textContent`，不拼 innerHTML；不引外部 CDN。

### 管理员账号（API 方式）

- 流程：`GET /api/admin/user/get?id=1` → 改 `username` / `password` → `POST /api/admin/user/update`
- 必须提交**完整 User 对象**：`UpdateUser` 只补齐 `PwdHash/Salt/OtpSecret`，`base_path / permission / allow_ldap / sso_id` 用提交值，漏传会被清零
- `role` 不可改；admin 不可禁用；`username` 有唯一约束
- 改完不需要重启，admin token 不变，伴侣应用不受影响
- 无 curl 时回退 CLI（`openlist admin set`，会短暂停服务）；用户名需要 sqlite3 才能改

## WebUI

`webroot/` 三个文件，无构建步骤：

- `index.html`：状态、更新、配置、改密、迁移、日志
- `app.js`：`ksu.exec` 兼容层（KernelSU 回调签名 + APatch 同步返回）、参数校验、进度轮询
- `style.css`：跟随系统深浅色

进度：`control.sh` 把 `stage=` 写到 `/data/local/tmp/openlist_update.progress`，WebUI 每秒读取显示。

## 兼容性

| 管理器 | WebUI | control.sh |
|---|---|---|
| KernelSU | ✅ | ✅ |
| APatch | ✅ | ✅ |
| Magisk | ❌（无 webroot） | ✅（终端/action.sh） |

## 测试记录

本地用假模块目录验证：

- `status` 未运行/运行中、`start`、`stop` 正常
- `config-save` 中文路径通过；端口 99999/0 被拒；`/115/;rm -rf` 被拒
- `migrate-data` 复制 + 文件数校验 + 改写 service.sh 正常
- `migrate-bin` 复制 + 改写两处变量正常
- `passwd` 调用 `openlist admin set` 正常
- `check` 返回 v4.2.10；`update --force` 真实下载 165MB ARM64 二进制、md5 通过、替换成功（proot 内无法运行 Android ELF，启动失败符合预期，回滚提示正确）

## 已知限制

- Magisk 无 WebUI 入口。
- 更新依赖 GitHub 可达，代理不可用时失败。
- 跨分区迁移（/data → /sdcard）会丢失属主权限，SQLite 性能下降。
- `update` 同步执行，下载期间 WebUI 只能显示阶段，不显示百分比。
- 改密后已登录会话不会失效。
