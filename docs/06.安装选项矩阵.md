# 06. 安装选项矩阵

`customize.sh` 只用音量键问两件事：二进制放哪、数据放哪。管理员账号不在这问，交给网页安装向导（OpenList 从 v4.2.10 起，没初始化就不会自动建 admin）。

## 选择项

| 菜单 | 选项 | 含义 |
|---|---|---|
| 二进制位置 | 1 | `/data/adb/OpenList/bin`（数据区，卸载能单独清） |
| | 2 | `$MODDIR/bin`（模块目录内） |
| | 3 | `$MODDIR/system/bin`（重启后由模块挂到 `/system/bin`） |
| 数据目录 | 1 | `/data/adb/OpenList` |
| | 2 | `/sdcard/Android/OpenList`（跨分区，见下方注意） |

`service.sh` 里两行由 sed 替换占位符写入：

- `OPENLIST_BINARY`：选项 1 写绝对路径；选项 2/3 写字面量 `$MODDIR/...`，运行时由 `service.sh` 自己展开
- `DATA_DIR`：直接写绝对路径

## 六种组合

| # | 二进制 | 数据 | 二进制落点 | `OPENLIST_BINARY` | `DATA_DIR` |
|---|---|---|---|---|---|
| 1 | 1 | 1 | `/data/adb/OpenList/bin/OpenList` | 绝对路径 | `/data/adb/OpenList` |
| 2 | 1 | 2 | 同上 | 绝对路径 | `/sdcard/Android/OpenList` |
| 3 | 2 | 1 | `$MODDIR/bin/OpenList` | `$MODDIR/bin/...` | `/data/adb/OpenList` |
| 4 | 2 | 2 | 同上 | `$MODDIR/bin/...` | `/sdcard/Android/OpenList` |
| 5 | 3 | 1 | `$MODDIR/system/bin/OpenList` | `$MODDIR/system/bin/...` | `/data/adb/OpenList` |
| 6 | 3 | 2 | 同上 | `$MODDIR/system/bin/...` | `/sdcard/Android/OpenList` |

不管选哪种，安装都会：

1. 按架构挑二进制：包内 `openlist-<arch>` → Download 里的 `openlist-android-<arch>.tar.gz` → 在线下载，改名成 `openlist` 放进目标位置，`chmod 755`
2. 选项 3 额外 `chcon u:object_r:system_file:s0`
3. 删掉包里其它架构的二进制（完整包带两份）
4. sed 替换 `__PLACEHOLDER_BINARY_PATH__` / `__PLACEHOLDER_DATA_DIR__`，替换完 grep 一遍，有残留就 `abort`
5. `chmod 755 control.sh`

## 架构矩阵

`customize.sh` 同时看框架给的 `$ARCH` 和 `ro.product.cpu.abi`，两者对不上时以能识别出的为准：

| `$ARCH` | abi | 目标 | 二进制名 |
|---|---|---|---|
| `arm64` | `arm64-v8a` | arm64 | `openlist-arm64` |
| `arm` | `armeabi-v7a` / `armeabi` | arm | `openlist-arm` |
| `x86_64` / `amd64` | `x86_64` | amd64 | `openlist-amd64` |
| `x86` / `i386` / `i686` | `x86` | 386 | `openlist-386` |
| 空 | `arm64*` | arm64 | `openlist-arm64` |
| 空 | `armeabi*` / `arm*` | arm | `openlist-arm` |
| 空 | `x86_64*` | amd64 | `openlist-amd64` |
| 空 | `x86*` | 386 | `openlist-386` |
| 都不匹配 | — | `abort` | — |

在线下载调 `control.sh fetch-bin <arch> <版本>`，走 `releases/download/vX.Y.Z/` 固定路径，不消耗 GitHub API 额度、不需要 token，下载的二进制版本与模块版本严格一致。安装期把 `NO_RANK=1` 打开，跳过 15 个镜像的并发测速（那要 8 秒，安装界面干等着难受），直接按内置顺序试。

## 五个产物

| 包 | 内含 | 说明 |
|---|---|---|
| `openlist-magisk-vX-arm64.zip` | arm64 | 单架构，`update-arm64.json` |
| `openlist-magisk-vX-arm.zip` | arm | 单架构，`update-arm.json` |
| `openlist-magisk-vX-amd64.zip` | amd64 | 单架构，`update-amd64.json` |
| `openlist-magisk-vX-386.zip` | 386 | 单架构，`update-386.json` |
| `openlist-magisk-online.zip` | 无 | 纯在线，约 76 KB，`update.json` |

每个架构包只带一份二进制，不再有双架构或 full 包。

`1.yml` 的做法：为每个架构建一个目录副本（281 KB），`sed` 注入该架构的 `version` / `versionCode` / `updateJson`，`zip -r` 打成包，再 `zip -j` 把二进制塞到包根目录。`zip -j` 只存文件名、不建目录，正好对上 `customize.sh` 里 `$MODROOT/openlist-<arch>` 的查找路径。

`online.yml` 的做法：同样复制一份目录，注入 online 版本号（`updateJson` 保持指向仓库根 `update.json`），`zip -r` 打包，包内无二进制。

## 安装期数据迁移

更新安装时，旧模块目录还在（框架先解压到 `MODPATH`，`customize.sh` 跑完才覆盖），所以能读到上一版的 `DATA_DIR`。检测到旧数据（有 `data.db`）且和这次选的目录不同，就会多问一次：

| 操作 | 结果 |
|---|---|
| 音量+ | 迁移到新目录，校验通过后删旧目录 |
| 音量- / 90 秒没操作 | 跳过，旧数据留着，装好后可以在 WebUI 里迁 |

如果选的是「二进制在 `/data/adb/OpenList/bin`」又要把数据迁走，安装脚本会先把二进制复制一份到模块 `bin/`（复制不是移动，迁移失败也不影响旧模块），迁移成功后旧目录连旧二进制一起删。

迁移放在安装流程的**最后一步**：前面占位符替换、校验都过了才动数据，避免「数据删了、安装却失败」这种半成品状态。

## 安装期二进制位置切换

三个位置：`/data/adb/openlist/bin`（选项 1）、模块 `bin/`（选项 2）、模块 `system/bin/`（选项 3）。

`customize.sh` 会从旧模块的 `service.sh` 读出上一版用的 `OPENLIST_BINARY`，和新位置对比：

| 情况 | 处理 |
|---|---|
| 位置没变 | 直接覆盖安装（新二进制替换旧的） |
| 位置变了，旧的在模块目录内 | 不用管，模块目录会整体替换 |
| 位置变了，旧的在模块目录外（选项 1） | **删掉旧位置的二进制**，空目录一起删，避免两份互相打架 |

删旧文件放在安装流程最后，数据迁移之后再执行，免得影响迁移时对旧进程的判断。旧文件删不掉（还在跑）时只打警告，不中止安装。

## 管理员账号

**安装脚本不碰密码。**

装完重启，浏览器打开 `http://IP:端口`，首次访问会引导你设管理员账号密码。设完之前 WebUI 里存储、离线任务会提示「还没有管理员账号」；设完就全好了（WebUI 用的是 admin token）。

早期版本在 `customize.sh` 里调 `OpenList admin set` 是无效的：admin 不存在时它只打一行日志就返回，退出码还是 0，看着像成功了，其实啥都没写。结果是库里只有 disabled 的 guest，所有 `/api/admin/*` 全 500。

## 怎么在没有真机的情况下测

造一个假的 Magisk 环境就行：

- 变量：`MAGISK_VER`、`MODPATH`、`TMPDIR`、`API`、`ARCH`、`IS64BIT`
- 函数桩：`ui_print`、`abort`、`getprop`、`getevent`、`sleep`、`chcon`
- 按键：`getevent` 桩按队列吐 `EV_KEY ... KEY_VOLUMEDOWN DOWN`，down 切换、up 确认
- 假二进制：两个 `OpenList-arm*` 换成只会回 `admin set` 的脚本

跑完查 `service.sh` 的两个变量、二进制落点权限、占位符残留、`module.prop`。

再补一层运行时：用 `ip` / `getprop` / `ss` 桩启动 `service.sh`，确认能拉起进程、算得出 IP 和端口、description 变成「【运行中】当前地址：http://IP:PORT | PID…」。

沙箱里 `/sdcard` 只读，测「数据目录选 2」时把常量换成可写目录单独跑一遍，验证逻辑本身没问题就行。

## 剩下的风险

1. **包体大**：现在两份架构二进制都塞在包里，体积翻倍。要不要改成安装时在线下载，见根目录 README 的征求意见。
2. **`uninstall-user.sh` 的交互只对手动执行有效**：Magisk 卸载走 `uninstall.sh`，没有交互。
3. **迁移时新目录会多一份 `bin/`**：源 `bin` 要保留（二进制在里面），复制时也跟着过去了，冗余但无害。
