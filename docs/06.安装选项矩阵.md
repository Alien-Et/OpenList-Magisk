# 06. 安装选项矩阵

`customize.sh` 用音量键做三次选择：二进制位置、数据目录、是否把初始密码改成 `admin`。本文把 3×2×2 = 12 种组合的实际落点、模拟方法和本次检查发现的问题记录下来。

## 选择项

| 菜单 | 选项 | 含义 |
|---|---|---|
| 二进制位置 | 1 | `/data/adb/openlist/bin`（数据区，卸载时可单独清理） |
| | 2 | `$MODDIR/bin`（模块目录内） |
| | 3 | `$MODDIR/system/bin`（模块目录内，重启后由模块挂载到 `/system/bin`） |
| 数据目录 | 1 | `/data/adb/openlist` |
| | 2 | `/sdcard/Android/openlist`（跨分区，见下方注意） |
| 初始密码 | 1 | 不修改，沿用 OpenList 默认 |
| | 2 | 改成 `admin`，并把密码写进 `$DATA_DIR/初始密码.txt` |

`service.sh` 里的两个变量由安装时 sed 替换占位符写入：

- `OPENLIST_BINARY`：选项 1 是绝对路径；选项 2/3 写成字面量 `$MODDIR/bin/openlist`、`$MODDIR/system/bin/openlist`，运行时由 `service.sh` 自己展开 `MODDIR`。
- `DATA_DIR`：直接写绝对路径。

## 12 种组合的落点

|---|---|---|---|---|---|---|---|
| 1 | 1 | 1 | 不改 | `/data/adb/openlist/bin/openlist` | 绝对路径 | `/data/adb/openlist` | 无 |

| 3 | 1 | 2 | 不改 | 同上 | 绝对路径 | `/sdcard/Android/openlist` | 无 |
| 4 | 1 | 2 | 改 | 同上 | 绝对路径 | `/sdcard/Android/openlist` | `/sdcard/Android/openlist/初始密码.txt` |
| 5 | 2 | 1 | 不改 | `$MODDIR/bin/openlist` | `$MODDIR/bin/openlist` | `/data/adb/openlist` | 无 |
| 6 | 2 | 1 | 改 | 同上 | `$MODDIR/bin/openlist` | `/data/adb/openlist` | `/data/adb/openlist/初始密码.txt` |
| 7 | 2 | 2 | 不改 | 同上 | `$MODDIR/bin/openlist` | `/sdcard/Android/openlist` | 无 |
| 8 | 2 | 2 | 改 | 同上 | `$MODDIR/bin/openlist` | `/sdcard/Android/openlist` | `/sdcard/Android/openlist/初始密码.txt` |
| 9 | 3 | 1 | 不改 | `$MODDIR/system/bin/openlist` | `$MODDIR/system/bin/openlist` | `/data/adb/openlist` | 无 |

| 11 | 3 | 2 | 不改 | 同上 | `$MODDIR/system/bin/openlist` | `/sdcard/Android/openlist` | 无 |
| 12 | 3 | 2 | 改 | 同上 | `$MODDIR/system/bin/openlist` | `/sdcard/Android/openlist` | `/sdcard/Android/openlist/初始密码.txt` |

所有组合都会：

1. 把压缩包里的 `openlist-arm64` 或 `openlist-arm` 重命名为 `openlist` 放到目标目录，`chmod 755`；
2. 选项 3 额外对二进制做一次 `chcon u:object_r:system_file:s0`；
3. 删掉没用到的那份架构二进制（包里同时带 arm 和 arm64）；
4. 用 sed 把 `service.sh` / `action.sh` 的 `__PLACEHOLDER_BINARY_PATH__`、`service.sh` 的 `__PLACEHOLDER_DATA_DIR__` 替换掉，替换后 grep 校验，有残留就 `abort`；
5. `chmod 755 control.sh`。

**初始密码不是安装时写进数据库的**。OpenList v4.2.10 起，未初始化时不再自动创建 admin（改为等 Web 安装向导）。安装脚本只把密码写进 `$DATA_DIR/初始密码.txt`，`service.sh` 启动时读取它并 `export OPENLIST_ADMIN_PASSWORD`，OpenList 首次启动才会真的建出 admin 用户。

早期版本在 `customize.sh` 里调 `openlist admin set` 是**无效的**：admin 不存在时该命令只打一行日志就返回，退出码仍是 0，看起来成功但密码没生效。副作用是 DB 里只有 guest，所有 `/api/admin/*` 返回 `500 record not found`，WebUI 的存储、离线任务、设置全部报错。

## 模拟方法

不需要真机。在沙箱里造一个 Magisk 安装环境：

- 变量：`MAGISK_VER`、`MODPATH`（模块临时目录）、`TMPDIR`、`API`、`ARCH`、`IS64BIT`
- 函数桩：`ui_print`、`abort`、`getprop`、`getevent`、`sleep`、`chcon`
- 按键序列：`getevent` 桩按预设队列吐出 `EV_KEY ... KEY_VOLUMEDOWN DOWN`，用 down 切换、up 确认
- 假二进制：`openlist-arm64` / `openlist-arm` 换成只响应 `admin set` 的脚本

跑完检查 `service.sh` 的两个变量、二进制落点与权限、占位符残留、`初始密码.txt`、`module.prop`。

再补一层运行时验证：用 `ip` / `getprop` / `ss` 桩启动 `service.sh`，确认能拉起进程、能算出 IP 和端口、并把 `module.prop` 的 description 改成「【运行中】当前地址：http://IP:PORT | PID…」。

沙箱里 `/sdcard` 只读，验证「数据目录选 2」时把常量换成可写目录单独跑一遍，确认逻辑本身没问题。

## 本次检查发现并修复的问题

| 问题 | 影响 | 处理 |
|---|---|---|
| `control.sh` / `uninstall*.sh` 从 `service.sh` 文本读出的 `$MODDIR` 不会二次展开 | 选 2/3 装完，WebUI 启动报「二进制不存在: $MODDIR/system/bin/openlist」，但文件明明在 | 加 `expand_moddir()`，把字面量 `$MODDIR` 换成真实模块目录 |
| `customize.sh` 里 `$MODDIR` 从未定义 | 菜单显示成「2、/bin」「3、/system/bin」，用户以为装到根目录 | 侦探块后补 `MODDIR="${MODDIR:-$MODROOT}"` |
| 三个脚本用 `MODDIR="${0%/*}"` 取目录 | `sh service.sh` 这类相对路径调用会得到 `service.sh`，日志写到 `service.sh/service.log` 直接失败 | 统一改成 `cd + pwd` 转绝对路径，失败再回退 `/data/adb/modules/openlist` |
| `until_key()` 在 `getevent` 不可用时无限空转 | 安装卡死，没有任何提示 | 加计数，约 90 秒无输入按默认选项（up）继续 |
| 脚本权限 | git 里记录为 644，手动 `./control.sh` 会 permission denied | 六个脚本统一 `chmod 755` |

## 本次一并处理的问题

| 问题 | 处理 |
|---|---|
| 卸载即删数据 | `uninstall.sh` 改为默认保留数据、只删二进制；要连数据一起删，卸载前 `touch $MODDIR/.delete_data_on_uninstall` |
| 架构判断覆盖框架变量 | 优先用框架给的 `$ARCH`，缺失才回退 `ro.product.cpu.abi`；`x86` / `x86_64` 直接 `abort` 并说明只提供 arm / arm64 |
| 数据目录不可写无提示 | 选择后 `mkdir -p` + `-w` 检查，不可写时打印警告、原因和补救办法，不中断安装 |
| 密码菜单排在「安装完成」之后 | 密码选择移到「✨ 安装完成」之前 |
| WebUI 硬编码模块目录 | 从 `location.pathname` 反推 `.../webroot/index.html` 的上级目录，推导失败才回退默认 id |

## 仍存在的风险

1. **安装包同时带两份架构二进制**：体积约翻倍。可以拆 full / lite 包（lite 安装时在线下载），但 recovery 环境经常没有网络，必须有 full 包兜底，所以暂时不拆。
2. **`uninstall-user.sh` 的交互选择只在手动执行时有效**：Magisk 卸载走的是 `uninstall.sh`，没有交互。
