# 05. 迁移与路径

## 与安装脚本的对应

安装时固定选项：

| 类型 | 选项 |
|---|---|
| 二进制 | `/data/adb/openlist/bin`、`$MODDIR/bin`、`$MODDIR/system/bin` |
| 数据目录 | `/data/adb/openlist`、`/sdcard/Android/openlist` |

WebUI 迁移页提供同样的预设胶囊，也允许自定义路径（范围是安装脚本的超集）。

## 数据目录迁移

```
停止服务（等 pgrep 为空，必要时 kill -9）
  → cp -a 旧目录/. 新目录/
  → 校验文件数
  → 校验 data.db 的 md5
  → 二进制若住在旧目录里：搬到 $MODDIR/bin/openlist 并改 service.sh/action.sh
  → 改 service.sh 的 DATA_DIR=
  → 改新目录 config.json 的绝对路径
  → rm -rf 旧目录（删不干净就报错）
  → 启动
```

### 迁移 = 移动，不留双份

复制 + 三项校验全部通过后才删源，任何一步失败都保留源目录并回滚服务状态。

两个例外说明：

- **二进制在旧数据目录里**（安装选项 1）：先 `mv` 到 `$MODDIR/bin/openlist` 再删源，
  否则 `rm -rf` 会把它一起删掉。不搬进新数据目录，是因为 `/sdcard` 通常 `noexec`，
  搬过去服务起不来。
- 复制阶段 `cp -a` 会把旧 `bin/` 里的二进制一起拷过去，删源后会清掉新目录里的这份多余副本。

`$MODDIR/bin` 已有另一份**内容不同**的二进制时直接中止并提示先「迁移二进制」，
不覆盖用户的文件。

### 为什么要改 config.json

OpenList 的 `config.json` 里是绝对路径：

- `temp_dir`
- `database.db_file`
- `bleve_dir`
- `log.name`

只改 `service.sh` 的 `DATA_DIR` 不够：OpenList 启动后仍会读旧路径，等于没迁移；旧目录删了会直接起不来。

迁移时把新目录 `config.json` 里所有 `"旧目录` 前缀替换为 `"新目录`。

## 二进制迁移

```
停止服务（等 pgrep 为空）
  → 复制到目标
  → chmod 755
  → 目标是模块 system/bin 时 chcon system_file
  → 改 service.sh 和 action.sh 的 OPENLIST_BINARY=
  → 校验新旧一致（md5，无 md5sum 时比字节数）后删除旧二进制
  → 旧位置是 <目录>/bin/xxx 且已空则把空 bin 目录收掉
  → 启动
```

校验不一致时**不删**旧文件，只回传 `warn=`，避免把唯一可用的一份删掉。

### /system/bin 的处理

Magisk/KernelSU 下 `/system` 是 overlay，直接写 `/system/bin/openlist` 重启即丢。

所以输入 `/system/bin/openlist` 会自动映射到 `$MODDIR/system/bin/openlist`：

- 写真实文件，立即能用
- 重启后模块把该目录挂到 `/system/bin`，命令行同样可用

## 安装期迁移（customize.sh）

更新安装时旧模块目录还在（框架先解压到 `MODPATH`，`customize.sh` 跑完才覆盖），
所以安装脚本能读出上一版的 `DATA_DIR`：

```
读 /data/adb/modules/openlist/service.sh 的 DATA_DIR
  → 与本次选的目录不同且里面确实有 data.db？
  → 显示占用/可用空间，音量+ 迁移 / 音量- 跳过（90 秒无操作按跳过）
  → 音量+：sh control.sh migrate-core <旧> <新> [旧二进制]
      复制 → 文件数 → data.db md5 → 搬二进制（若在旧目录里）→ 删旧目录
  → 失败：打印 error 行并 abort，旧数据原样保留
```

要点：

- **默认跳过**：刷机时没人看着也不会动数据
- **失败不删源**：任何一步校验不过就停在原地，旧模块重启后仍能用
- **二进制后搬**：校验通过后才把旧目录里的 `openlist` 挪到模块 `bin/`，
  避免迁移失败时旧模块的二进制已经不在原位
- **数据目录里的 `bin/` 不参与复制**：二进制由安装选项单独决定位置
- 目标非空、目标是源的父子目录、空间不足都会在复制前拦掉

## 路径校验

| 场景 | 规则 |
|---|---|
| 数据目录 | 目标不能位于模块目录内 |
| 数据目录 | 目标不能是当前数据目录的子目录 |
| 数据目录 | 目标不能是当前数据目录的父目录 |
| 二进制 | 不能放进 `webroot` |
| 二进制 | 不能放进数据目录 |
| 二进制 | 目标文件不能已存在 |

拒绝原因会原样返回，WebUI 直接显示。

## fix-paths

迁移后如果 `action.sh` 或 `config.json` 还指向旧路径：

```sh
sh /data/adb/modules/openlist/control.sh fix-paths
```

- 以 `service.sh` 的 `OPENLIST_BINARY` 为准，同步 `action.sh`
- 从 `config.json` 的 `db_file` 推断旧目录，替换所有 `"旧目录` 前缀

注意：它**以 `service.sh` 为准**。如果 `service.sh` 本身错了，先把 `DATA_DIR=` 改对再执行。

## 卸载

`uninstall.sh` / `uninstall-user.sh` 不再写死路径：

- 从 `service.sh` 读 `OPENLIST_BINARY` / `DATA_DIR`
- 与默认的 3 个二进制位置、2 个数据目录合并清理

迁移到自定义路径后，卸载也能清到。

## 风险

- `/data` → `/sdcard` 跨分区：`chown/chmod` 无效，SQLite 在 FUSE 上性能下降
- 迁移期间必须有进程写 db 才能复制，所以先停服务、确认 `pgrep` 为空
- 源目录在迁移成功后自动删除；WebUI 迁移页会立刻刷新状态、路径体检和日志，不用手动刷新页面
